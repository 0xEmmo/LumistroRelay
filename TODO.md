# Lumistro Relay V1 — Todo

This outcome list reflects the owner-first direction. Public Foodician demo surfaces remain removed; Foodician is reserved for a later internal demo/evaluation.

## Completed outcomes

- [x] **Managed foundation and protected owner workspaces:** The project uses Manus OAuth, server-side membership-derived tenant scoping, an isolated workspace per authenticated owner, typed relational workspace/brand records, managed TypeScript diagnostics, and a synchronized route manifest. New owners never inherit the seeded Foodician brand.
- [x] **Owner-first public entry:** The public landing page describes Relay for business owners and provides a path to the authenticated workspace. It does not display Foodician, expose a demo CTA, or route to a public demo page/API.
- [x] **Owner-approved brand, catalogue, FAQ and channel setup:** Owners can save their name, website, menu link, industry, description, locations, opening hours, contacts, delivery/service areas, accepted payment methods, ordering/booking instructions, policies and brand voice; add products/services with category, description, exact optional price, variants/add-ons, availability and optional image URL; and create FAQs with approved answers and related phrases. Saved facts are tenant-scoped and treated as owner-approved. Instagram and WhatsApp can be simulated independently or together, and every state is visibly simulated; no account credential or live authorization is requested.
- [x] **Selectable owner setup and useful starters:** The owner can choose a business type, opening-day preset, individual weekdays and opening/closing times, common payment methods, ordering channels and brand voice, while retaining editable text for exceptions and custom facts. Industry-aware FAQ question starters are available. Saved approved hours, areas, payments, order instructions, locations, contacts, policies and menu links can be added as one-click FAQ starters with their exact saved answer, ready for the owner to review. Business/menu/image URLs are blank or credential-free HTTP(S) URLs.
- [x] **Useful, answerable receptionist test prompts:** A plain greeting such as “Hello” receives a warm built-in response using only the saved business name. Other test-question chips are derived from saved profile details, menu/catalogue, known product prices/availability or safe approved FAQs; a chip immediately runs the selected test. Unsupported availability questions and unsafe FAQ topics are not presented as answerable examples. A handoff check is visually separated as an optional safety test.
- [x] **Owner-approved menu, link and image replies:** For a menu request, Relay returns the exact saved menu link and/or a short list of saved catalogue items only when those owner records exist. If no menu link, catalogue item or approved menu FAQ exists, Relay safely hands off. Product images come only from owner-supplied validated image URLs; links/images are rendered as safe attachments with the exact source reference and retained in saved test history. No generated or model-selected URL/image is used.
- [x] **Grounded, draft-only receptionist:** The owner can test customer text through the server-side managed LLM using the owner’s approved records. It returns ANSWER/ASK/HANDOFF, confidence, intent, missing information, filtered lead details, internal reason and kind/field-specific source references. The server validates source references and builds factual ANSWER text from exact approved fields or FAQ text, not model-authored factual prose. The test is never sent to a customer; each run is stored with its decision, source records, mode, model and prompt version.
- [x] **Fail-closed safety rules and responsive owner states:** Complaints/problems, refunds, discounts, catering/custom/large orders, allergy/safety matters, explicit human requests, sensitive/legal/financial topics, unclear product/variant/booking availability, unsupported delivery estimates and missing required business facts are withheld for a person. ASK may request only one allowlisted safe detail using a fixed server-authored question; invalid, ambiguous, unsupported or irrelevant model output falls back to handoff. Setup preserves owner-entered values on recoverable errors, with clear loading, save, empty, error, simulation and not-sent states. Links and images are available in current results and saved test history.
