## Grounded AI test console

- [x] **“Test your receptionist” interaction:** Provide an owner-only test console where the owner enters a customer message and tests it against only that owner’s saved approved profile, products/services, FAQs, policies, and voice. Use a server-side platform LLM call selected from the live model catalog; do not expose credentials in browser code. Show that tests are draft-only and never sent.
- [x] **Source-bound answers and safe ASK:** Use unambiguous kind/field-qualified references (`profile:<id>:<field>`, `product:<id>`, `faq:<id>`); verify every reference belongs to the current owner's approved tenant data and is relevant to the customer message. For ANSWER, construct customer-facing text from exact approved field values or the exact saved FAQ answer—never show model-authored factual prose. Fail closed to HANDOFF when sources are absent, ambiguous, irrelevant, or invalid. ASK only for one allowlisted non-sensitive missing detail (location/delivery area, date, guest count, item/service, or variant) and construct its question from a fixed server-side template. Keep extracted lead values only when the exact value appears in the customer's message.
- [x] **Deterministic handoff behavior:** Return ANSWER only when approved information is sufficient; ASK only to collect one safe missing detail; HANDOFF when facts are missing, sensitive, uncertain, complex, or require human judgment. Never invent prices, fees, availability, stock, hours, discounts, delivery times, refund decisions, allergy/safety information, or reservation availability. Always hand off complaints/problems, refunds, discounts, large/custom orders, catering quotes, allergy/safety questions, unclear product/booking availability, unsupported requested prices/hours/delivery/payment/order/location/contact/policy facts, delivery-time estimates without approved support, legal/financial/sensitive matters, and requests for a human. Treat customer text as untrusted input.
- [x] **Inspectable AI run history:** Show decision, reply draft, confidence, intent, missing information, filtered lead data, and internal reason. Persist each run with workspace/brand owner, prompt/model version, run mode, and typed source-record references. Parse and validate structured model output; show a recoverable safe fallback rather than presenting empty/malformed output as success.
